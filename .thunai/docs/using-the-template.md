# Using Thunai in your project

## 1. Create your repository

Choose one:

- **Use this template** on GitHub (the repository is a template repository), then clone your new repository.
- **Existing repository:** skip to "Adopt Thunai in an existing repo" below.

## 2. Bootstrap

```text
python init.py
python init.py --non-interactive --name "Acme Shop" --packs web-nextjs,api-fastapi
python init.py --list-packs
```

Requires Python 3.10 or newer and nothing else. Then fill in `commands.*` and `docs.*` in `.thunai/config/project.config.json` and `.thunai/memory/who-owns-what.md`.

## 3. Remove the template's own project files

A repository created from this template still contains files about Thunai itself. Remove or replace them so they do not describe your project:

| File | Action |
|---|---|
| `LICENSE` | Replace with your own licence (this one is Thunai's copyright) |
| `README.md` | Replace with your project's README |
| `THIRD_PARTY.md` | Keep only the entries for skills you kept, or move the notices into your own file |
| `skills/LICENSE` | Keep while you keep the `test-driven-development` and `systematic-debugging` skills |
| `CHANGELOG.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md` | Replace with your own, or delete |
| `.github/ISSUE_TEMPLATE/`, `.github/PULL_REQUEST_TEMPLATE.md`, `.github/CODEOWNERS`, `.github/dependabot.yml` | Replace with your own |
| `.github/workflows/ci.yml` | Replace with your CI; keep a `python .thunai/sync.py --check` step |
| `.thunai/scripts/validate_template.py`, `.thunai/scripts/smoke_init.py`, `.thunai/docs/` | Delete (they test and document the template) |
| `init.py`, `adopt.py`, `TEMPLATE.md`, unused `packs/` | Delete once set up |

Do not delete the generated files (`.claude/`, `.opencode/`, `.github/agents`, `.github/instructions`, `.github/prompts`, `.github/skills`, `CLAUDE.md`, `.github/copilot-instructions.md`). Regenerate them with `python .thunai/sync.py`.

## 4. Start working

Open your AI tool and run `/orient`. See [.thunai/README.md](../README.md) for per-tool start-up and guardrail details.

## Staying up to date

Thunai follows semantic versioning; see [CHANGELOG.md](../../CHANGELOG.md). To take an update, diff the new release against your copy for `.thunai/src/`, `skills/` and `packs/`, merge what you want, then run `python .thunai/sync.py`.

## Adopt Thunai in an existing repo

One command, run from a clone or download of this template:

```text
python adopt.py ../my-repo --dry-run     # preview, writes nothing
python adopt.py ../my-repo               # asks for name, prefix, teams, packs
python adopt.py ../my-repo --non-interactive --name "Acme Shop" --packs web-nextjs,api-fastapi
```

Create a branch in your repo first (for example `git switch -c chore/add-thunai`); the script never runs git.

What `adopt.py` does:

- Copies `.thunai/`, `skills/`, `AGENTS.md` and `CLAUDE.md`. It leaves out the template's own `LICENSE`, `README.md`, CI, community files, `.thunai/docs/` and the template test scripts.
- Never overwrites an existing file. It merges `.gitignore`, `.gitattributes`, `.vscode/settings.json` and `.claude/settings.json` (your values win on a clash; the script lists them).
- Runs `init.py` in your repo (name, branch prefix, teams, packs, generation of the Copilot, Claude Code and OpenCode files), then removes `init.py` and `packs/` from it. Use `--keep-init` to keep them.
- Stops if `AGENTS.md`, `CLAUDE.md` or `.github/copilot-instructions.md` already exist and were not generated by Thunai. Re-run with `--force` to save them as `*.pre-thunai`, then move your content into the Thunai copies by hand. It also stops if `.thunai/` already exists.

Afterwards:

1. `git status`, review, then commit on your branch.
2. Fill in `commands.*` and `docs.*` in `.thunai/config/project.config.json` and the table in `.thunai/memory/who-owns-what.md`.
3. Check: `python .thunai/sync.py --check` and `python .thunai/hooks/test_git_guard.py`.
4. Open your AI tool and run `/orient`.

Requires Python 3.10 or newer.
